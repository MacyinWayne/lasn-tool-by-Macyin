## 一、怎么打开

### 推荐：双击

直接双击 **`tool/index.html`**（Windows 上默认用 Edge 打开）。
所有脚本、样式、角色数据都是本地文件，**不需要联网、不需要安装任何东西**。

> 为什么不是 `fetch` 读取 `data/structured/characters.json`？
> 浏览器在 `file://` 协议下读取本地 JSON 会被 CORS 拦截（Origin 为 null）。
> 因此角色数据在**构建期**固化成全局脚本 `tool/src/data/characters.js`，
> 页面用普通 `<script>` 引入 —— 这是本工具能「双击即用」的关键设计。

### 可选：本地静态服务器

```bash
node tool/serve.mjs          # http://127.0.0.1:8765/
node tool/serve.mjs 9000     # 自定义端口
```

只有本地调试才需要；日常使用直接双击即可。

### 数据更新（T1 产出新角色数据后）

```bash
node tool/scripts/build-characters.mjs   # 角色数据（详情页增强；也可用 build-data.mjs 全量）
node tool/scripts/build-scenarios.mjs    # 场景/训练方向/圣山 → src/data/scenarios.js
node tool/scripts/build-equipment.mjs    # equipment_merged.json → src/data/equipment.js（BBEquipmentData）
node tool/scripts/build-battle.mjs       # battle_loadout_v3.json + position_fit_v3.json + character_types_v3.json
                                         #   → src/data/battle.js（BBTBattleData：38×5 实战配装数据）
node tool/scripts/build-data.mjs        # 角色 + 派生评分全量
```

脚本读取 `data/structured/characters.json`（T1 结构化数据），归一化后生成
`tool/src/data/characters.js`；文件缺失或解析失败时自动降级为内置示例名单，
界面会显示「降级示例数据」提示。生成后刷新页面即可。

### 笔记契合（第 10 个 Tab）说明

- **同档等价**：同一档位（如「优」30-44）触发率相同 → 工具按「档位达成成本」而非分数最大化设计。
- **模式 A（常规养成配置，目标优）**：列出两本基础分合计 ≥30 的组合，可切换基础分降序（容错余量）/升序（最贴门槛）、
  按笔记角色排除；置顶最高基础分组合。
- **模式 B（极养成路径，目标 45+）**：按「最少词条星级 → 基础分降序」排序；显示缺口 need_bonus、最省词条方案、
  高亮「2 星内达成」（base ≥40，全局仅 3 条路径）与「3 星达成」；含养成行动清单与经济学结论。
- **假设开关**：每本最多 1 条契合词条、两本可叠（默认）/ 只单本生效 / 可叠多条 —— 切换后即时重算缺口与方案。
  数据原假设待游戏内核验；若实际只能单本生效，缺口大的组合会变为不可达。
- **运行时过滤**：矩阵 37×37 全量数据在浏览器里实时计算，主力与两本笔记所属角色都必须在「我的角色」内；
  未拥有笔记角色被排除时显示增量提示：「若获得【X】，最优组合变为 A+B → 极仅需 N 星词条」。
- **数据校验**：矩阵已通过 22/22 条摘要和、对角为 0、完全对称校验（张君宝《笔记契合关系一图流》2026.11.02 数据版，
  截图 OCR/人工转录）；**仍待客户端逐格 diff 复核**。当前 37/38：缺「百目鬼 剑」关系分。
- **每角色「最优笔记配置（待生成）」**：图鉴详情与笔记结果各保留一个占位区块
  （targetAttrs / dutySuitEntries / skillEntries / harmonyEntries / qualityTarget / harmonyTarget / basis=pending），
  明确标「待研究 / 推断·待养成逻辑定稿」；养成逻辑定稿后只需替换数据生成脚本，不改 UI。
- **不做**：笔记库存录入（用户确认非重点）——标记为未来可选功能。

## 三、核心公式与示例

### 训练收益（A 层，T3 model 口径）

```
单次训练收益 = ( 训练项基础 + (训练等级−1) × 3 + 人员加值 + 对口器材加值 + 角色技能固定加值 )
               × (1 + Σ训练加成 + 心情%) × (1 + 器材暴击%) × (1 + 场地%)
               + 主属性加值（尾项，不乘乘区）
副属性收益 = 主属性收益 × 副属性收益占比（默认 50%；用户实机观察约 33%~50%，T3 模型区间 30%~70%，待更多样本）
```

- A 层训练项基础：**投射 / 弹跳 / 防守 / 体能 / 运控 = 10；意识 = 8**（社区实测）
- 一个训练项同时提升**两项** A 层属性 —— **用户实机验证（2026-11-05 公测，训练界面预测值）**：
  投射→投射+运控 / **弹跳→弹跳+意识** / 防守→防守+体能 / **体能→体能+弹跳** / **运控→运控+防守** / **意识→意识+体能**
  （旧版 `edu_train_conf` 原文配对 弹跳→体能、体能→投射、运控→意识、意识→弹跳 已被实机推翻，以实机为准）
- 心情加成（多源一致）：极好 +20% / 好 +10% / 一般 0 / 差 −10% / 极差 −20%
  —— 与 Σ训练加成加算进同一乘区（位置为推断）
- 副属性占比、场地加成位置：**待验证**，验证器 Tab 可用实测样本反解

### 表情爆发（2026-11-05 用户实测定稿）

```
爆发倍率 = (1 + Σ每个参与者的(表情基础 + 角色技能加成)) × 一致乘区

表情基础：大笑 20% / 微笑 10% / 哭脸 0%
参与者数：经理 + 陪练 + 主练（满编 6；无人=主练 1；单经理/单人=2；2 陪练=3…）
          希雅二星虚空人 +1~3 → 上限 9
一致乘区（实测表值）：仅当「全部参与者表情同款」且人数 ≥2 时触发（任意表情类型，含全哭脸）
          2 人 = ×1.5；3 人 = ×1.8；4 人 = ×2.0；5 人 = ×2.2；6 人 = ×2.5（真崎再 +0.25）
          7/8/9 人 = round1Banker(1+0.25×人数) 推算 = ×2.8 / ×3.0 / ×3.2（待实测）
          单人训练 / 混合表情不触发；混合只线性相加
```

**用户实机锚点（工具内可一键复现）**：

```
2 哭脸一致          = 1.0 × 1.5 = 150%（全哭脸也触发）
3 微笑一致          = (1 + 3×10%) × 1.8 = 1.3 × 1.8 = 234%
3 大笑一致          = (1 + 3×20%) × 1.8 = 1.6 × 1.8 = 288%
4 大笑一致          = (1 + 4×20%) × 2.0 = 1.8 × 2.0 = 360%
5 微笑一致          = (1 + 5×10%) × 2.2 = 1.5 × 2.2 = 330%
6 大笑一致 + 望月8% + 龙宫寺4% + 真崎0.25
                   = (1 + 6×(20+8+4)%) × (2.5+0.25) = 2.92 × 2.75 = 803%
1 大笑 + 1 微笑     = 1 + 20% + 10% = 130%（混合，只线性相加）
3 大笑 + 1 哭脸     = 1 + 3×20% + 0 = 160%（有同款但非全一致 → 不乘一致）
```

> 一致乘区规律：`1+0.25n` 后按 **1 位小数银行家舍入**（1.75→1.8、2.25→2.2、2.75→2.8、3.25→3.2）；
> 2/3/4/5/6 人已实测，7/8/9 人为该规律推算·待实测。
> 旧模型「每格统一 20% + 固定 6 格 + 一致倍率固定 2.5」已降级为 **legacy 对照**（工具内保留，不参与新默认）；
> 803% 示例在新模型下仍是「6 人大笑全一致 + 望月 8% + 龙宫寺 4% + 真崎 +0.25」的合法结果。

**希雅二星「虚空人」（用户实测，2026-11-05）**：训练队基础 6 人 = 经理1 + 陪练4 + 主练1；
希雅二星在场额外带来 1~3 个虚空人（幻影队友），虚空人表情必定与某个真人一致。
若真人 6 人已锁满一致，虚空人必定跟随 → 锁 9 人稳定可达；若真人未锁满，虚空人会随机跟随不同真人、反而更难齐。
注意：7/8/9 人一致乘区为推算·待实测（工具标「推算」；旧模型 legacy 区有 ×2.75 估算，仅对照）。
来源：`knowledge/表情机制_希雅二星虚空人.md` + 用户实机（2026-11-05；分布/独立随机等待游戏内确认）。

结论：表情加成线性相加会「稀释」；一致乘区是独立乘法、且只认「全员同款」——所以要么锁满一致，要么别赌混合。

### 属性体系（本项目最有价值的机制发现之一）

游戏有**三层属性**（客户端配置 `cw_conf.archive` 逆向确证，A/B/C 不能混算）：

- **A 层 · 培养/训练六属性**：投射、弹跳、防守、体能、运控、意识 —— 训练公式用这套
- **B 层 · 一级属性点数**：进攻（→投射+攻筐）、防守（→防投+护筐）、组织（→传球+突破）、
  对抗（→篮板+逼抢）、体能（→耐力+爆发）
- **C 层 · 二级比赛属性（14 项）**：投射 / 攻筐 / 防投 / 护筐 / 传球 / 突破 /
  篮板 / 逼抢 / 耐力 / 爆发 / 体力 / 体力上限 / 能量 / 能量上限
  —— GameKee 图鉴六维只是 C 层**子集**；图鉴评分只在 C 层内部比较，不与 A 层混算

公式卡 Tab 有完整的「属性体系说明」卡片与训练配对表。
